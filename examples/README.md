# Examples — 精选输入输出样例

本目录保存**人工核对过的标准输入与期望输出**，用于：

- 展示 3wagent 在真实跨境政策问题上的分析形态
- 作为回归基准（新改动不应让输出契约退化）
- 帮助新读者理解「一个问题进来、一份结构化结论出去」的完整链路

这些是**精选、可提交、稳定**的参考样例，与 `reports/`（每次运行本地生成、被 `.gitignore` 忽略的产物）刻意区分开。

| 目录 | 区别 | 是否纳入版本库 |
|------|------|----------------|
| `examples/` | 人工核对的标准输入 + 期望输出，作为展示与回归基准 | 是 |
| `reports/` | Lead Policy Agent 每次运行实际生成的 `report.md` / `report.pdf` | 否（仅保留 `.gitkeep`） |

---

## 样例清单

### 1. `cn-service-fee-tax/` — 纯粹税务问题

- **`input.md`** — 中国境内 A 公司向香港 B 公司支付技术服务费 100 万美元，服务完全在境外完成，问是否需要代扣代缴增值税与企业所得税。
- **`expected-output.md`** — 完整 5 项输出：判定增值税需代扣 6%（2026《增值税法》消费地原则）、企业所得税无需代扣，并给出现行法规清单、修订关系、风险提示与可靠性评估。
- **`Screenshot *.png`** — 该样例背后的原始素材截图，保留以说明问题来源与人工核对依据。

演示重点：**单一领域（税务）问题如何独立分析**，不强行牵扯外汇。

### 2. `cn-sg-service-fee-cross-domain/` — 跨领域问题

- **`input.md`** — 中国境内 A 公司向新加坡 B 公司支付技术咨询费 50 万美元，技术人员定期来华、双方存在关联关系，同时涉及外汇手续、税种判断与转让定价。
- **`expected-output.md`** — 完整 5 项输出，覆盖外汇备案、增值税代扣、常设机构判定、关联交易转让定价等多条线索。

演示重点：**跨领域问题如何拆解**——税务为主分析、资金合规为辅，并叠加民商/关联交易风险。

## 输出契约对照

两个 `expected-output.md` 都严格遵循 `config/output-contract.yaml` 定义的结构：

```
【问题分类】【结论或考量维度】【类案与公开答案】
【涉及现行法规】（重点）【法规修订关系】
【风险提示】【结论可靠性】【报告文件】
```

> 说明：样例中的法规条款、案号与日期用于演示分析结构与来源分级方法。实际使用时，
> 仍需由 `rag-retriever` 检索官方来源、`regulatory-validity-verifier` 校验时效、
> `citation-verifier` 校验引用后，方可作为正式依据。
